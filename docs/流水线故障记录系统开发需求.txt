流水线故障记录系统开发需求
一、项目目标
开发一个用于记录和跟踪流水线故障的小型 Web 应用，支持从故障登记、处理跟进到处理完成的基本业务闭环。页面应简洁、清晰，便于操作。
二、业务功能
1. 故障登记：能够记录故障所属流水线、发生位置、发生时间和故障现象等必要信息。具体字段、数据表结构和接口由开发者根据业务需求自行设计。
2. 故障查询：能够查看故障列表，按流水线和处理状态筛选，并查看单条故障的详细信息。列表默认优先展示最近发生的故障。
3. 故障处理：能够将故障从待处理推进至处理中、已完成，并补充和保存处理说明；完成处理时应有相应说明。后端应检查状态流转，已完成的记录不能直接恢复为待处理。
4. 校验与反馈：后端应校验必要信息，对无效输入、不存在的记录和不合理操作返回明确错误。前端应展示加载、空数据、操作成功和请求失败等状态，提交期间避免重复点击。
5. 数据保存：故障信息和处理结果应保存到数据库，刷新页面或重启服务后仍可查询。
三、技术与项目结构
1. 前端使用 Vue 3、TypeScript、Vite、Vue Router、TanStack Query、Zod，视觉效果自由发挥；后端使用 FastAPI、Pydantic 2、SQLAlchemy 2；数据库使用 SQLite。
2. 前后端放在同一项目中，使用独立目录（如 frontend、backend），分别管理依赖，能够分别安装和启动。
四、运行与配置要求
1. README 应说明实际验证过的操作系统、Python 及其他必要运行环境的版本，并包含环境准备、依赖安装、配置、数据库初始化、前后端启动和基本验证步骤。允许采用自动建表方式初始化 SQLite。
2. 验收时，应能够在干净环境中仅按照交付材料完成安装、初始化和启动，不需要额外补充文件或口头操作步骤。
五、成果交付
1. 开发过程使用本地 Git 管理，按功能或阶段持续提交，提交说明应清楚描述修改内容。
2. 最终提交项目压缩包，包含完整源代码、依赖声明及版本固定文件、配置示例、数据库初始化相关代码、README，以及完整的 .git 目录，确保解压后可以查看提交历史。
3. 压缩包不包含虚拟环境、node_modules、缓存，可以有模拟数据。
