流水线故障记录系统：第二阶段增量需求
一、本轮目标
在上次提交的项目基础上，增加故障优先级功能，并使用 Alembic 完成数据库结构升级。沿用原技术栈、SQLite 数据库及前后端独立目录结构，具体字段命名和接口设计自行确定。
二、业务需求
1. 故障优先级分为“普通”和“紧急”。新建故障时可选择优先级，默认“普通”；在详情中可查看和修改优先级，修改优先级不改变故障处理状态。
2. 故障列表展示优先级，并支持按优先级筛选及查看全部。优先级筛选可与原有流水线、处理状态筛选组合使用，列表仍按发生时间倒序展示。
3. 后端校验优先级取值，非法取值返回明确错误且不保存。前端提供修改成功或失败的反馈，提交期间避免重复操作。保存后刷新页面或重启服务，优先级仍然有效。
三、数据库迁移
1. 使用 Alembic 管理本次结构变更，提供迁移配置及脚本；空数据库能够通过迁移命令初始化为最新结构。
2. 上次项目通过自动建表产生的数据库，也应能够按文档步骤接入迁移并升级。已有故障统一设为“普通”，原有记录、编号、处理状态和处理说明保持不变，原有功能仍可使用。
3. 升级不得通过删除数据库、清空数据或重新录入原记录完成。README 应分别说明空库初始化和旧库升级的操作步骤。
四、开发与交付
1. 使用本地 Git 管理完整项目，保留可追溯的开发起点，并按迁移、后端、前端等实际修改内容合理拆分提交，提交说明准确描述改动。
2. 交付压缩包包含完整源码、依赖及版本固定文件、迁移文件、配置示例、更新后的 README 和完整 .git 目录；另保留一份含模拟数据的升级前数据库，供验证升级过程。
3. README 保留环境要求及前后端独立安装、启动说明，并补充本轮功能的基本验证步骤。压缩包不包含虚拟环境、node_modules、缓存或真实业务数据。
五、验收重点
验证优先级的默认值、修改、组合筛选及非法输入处理；分别验证空库初始化和旧库升级，确认旧数据保留；检查运行说明与本轮 Git 提交记录。
